# My Tomorrow Feature Survival Map

Status: FROZEN BEFORE CONSUMER NAVIGATION COLLAPSE

## Rule

The redesign is allowed to simplify navigation, not capability. Existing features are removed from primary navigation only after their user job has a clear home in the new journey and that replacement is tested.

## Target consumer structure

Primary consumer navigation:

1. My Tomorrow
2. Protected
3. Explore
4. You

This is a target structure, not permission to delete old routes immediately.

## My Tomorrow owns the daily answer

My Tomorrow should not become a menu of old cards. It owns the synthesis layer:

- What is coming?
- When?
- Safety impact.
- Money/exposure impact.
- Time/movement impact.
- What to protect.
- What to do.
- What changed.
- Why we think this.
- Who/what else the user has protected that may be affected.

Deep tools open only when the user asks for more detail or needs to perform a specialised action.

## Protected owns the reason to stay

Protected is where the user turns a one-off check into an ongoing relationship.

It contains saved homes, family members, school/work/shop locations, routes and later supported assets. It explains what is monitored and why.

Core safety monitoring remains useful on the free tier. Paid value should expand coverage, coordination, planning depth and history rather than withholding urgent safety information.

## Explore owns curiosity and discovery

Explore contains maps, active hazards, live reports, location search, route exploration and wider Nigeria intelligence. It is where a user can look beyond their personal briefing without making the daily home screen complicated.

## You owns control and history

You contains account, language, accessibility, appearance, notification preferences, plan, personal history and privacy/data controls.

## Institutional separation

Business, agency, insurer, logistics and other institutional tools should not be forced into the ordinary consumer navigation. Their existing command, intelligence, evidence, reporting, API and economic workflows survive as specialist workspaces connected to the same hazard/impact/evidence foundation.

## Removal gate

An old consumer route may disappear from primary navigation only when:

- its important job is present in one of the four target destinations;
- the replacement works on mobile and desktop;
- direct deep links still resolve or intentionally redirect to the new equivalent;
- existing user data is preserved;
- evidence/provenance is not lost;
- accessibility and language behavior are preserved;
- no safety-critical action takes more steps than before;
- QA proves the new path is not broken.

Until then, the old route stays available even if the new journey is being prototyped.
