# NaijaClimaGuard V2 User Journey

Status: PRODUCT FLOW BEFORE UI REDESIGN

This journey is deliberately simple. The user should not need to understand flood models, satellite data or climate science to receive value.

## One sentence the user should remember

**NaijaClimaGuard tells me what tomorrow could take from me before it happens, when it may happen, what I should protect and what I should do.**

## 1. First visit: value before registration

The first screen asks one useful question:

**What should we protect tomorrow?**

The user can use current location or search for a place.

NaijaClimaGuard immediately opens **My Tomorrow** without forcing account creation.

The first answer is structured around three things ordinary people understand:

**Safety** — Is anything dangerous developing around me?

**Money** — Is tomorrow likely to create avoidable cost, damage or disruption for me?

**Time** — Could my route, work, school or plans be disrupted?

Then it gives the action:

**Do this before [time].**

If nothing meaningful is developing, it says so clearly. A quiet day must never be turned into fake danger for engagement.

### Comparison with original build

Original: useful flood/risk information, but the citizen often had to interpret what the information meant.

V2: the first result is about the user's own day and action.

Judgment if implemented correctly: **CLEARLY BETTER.**

## 2. The first "wow" moment

The first useful result must answer, in one view:

- What is coming?
- When could it affect me?
- Is my area exposed?
- What could it affect?
- What should I protect?
- What should I do now?

The interface may expose evidence and model detail underneath, but the human answer comes first.

Example structure, not a fabricated live prediction:

**Something may affect your evening.**

Heavy rainfall is the strongest developing risk around your area between late afternoon and evening.

**Protect:** your normal route and anything left in a low-lying outdoor area.

**Do:** leave before the higher-risk window if practical and check the route again before setting out.

The exact content must always come from supported live data and validated model output.

### Comparison with original build

Original: strong warning/delivery thesis.

V2: preserves warning delivery and adds timing, personal exposure and a direct action.

Judgment: **CLEARLY BETTER if model evidence supports the timing.**

## 3. Save what matters

Only after the user receives value do we ask:

**Want NaijaClimaGuard to keep watching this for you?**

Account creation then has an obvious purpose.

The user can save human things rather than technical coordinates:

Home
Work
School
Shop
Family
Farm
A normal route
A vehicle/property/asset where supported

The user may rename them naturally, for example "Mum's house" or "My shop".

### Why this creates return

The user no longer opens a climate application to inspect Nigeria. They open it to check the things they care about.

## 4. Daily home: My Tomorrow

Every day the home screen answers one question:

**What changed for me since I last checked?**

The order is:

1. Most important change
2. When
3. What is exposed
4. What to do
5. Evidence/confidence if the user wants more detail

The screen should not reward endless scrolling. Its value is that it can be checked quickly and trusted.

A normal day can say:

**Nothing serious is developing around the places you protect. No action needed right now.**

A changing day can say:

**Your evening risk increased since this morning. Check your route before 4 PM.**

This is the daily return loop: the answer genuinely changes as forecast information and local evidence change.

### Comparison with original build

Original: strongest when flood danger existed.

V2: remains useful on normal days and across more validated hazards.

Judgment: **CLEARLY BETTER if users actually return. This must be measured after launch.**

## 5. Notifications: only when there is a reason

Notifications are not a feed of weather facts.

They should be sent for material changes such as:

- a protected place enters a meaningful risk window;
- timing changes enough to affect a planned action;
- risk level materially rises or falls;
- a new official advisory affects a protected place;
- a safer action or route becomes relevant;
- the previous warning has resolved and the outcome is available.

The message should contain the useful fact even before the app is opened.

## 6. After the event: prove whether we helped

After the predicted window closes, NaijaClimaGuard should not simply forget the warning.

It asks a tiny outcome question when useful:

**What happened there?**

Examples of answer types:

No problem
Road/transport disrupted
Flooding/water entered area
Business/work interrupted
Property/asset affected
Something else

The system can also compare the forecast with independent observed data where available.

This creates the **Prediction → Reality** record.

It has two purposes:

1. Give the user proof that NaijaClimaGuard is useful and accountable.
2. Build privacy-safe impact intelligence about what environmental conditions actually do in Nigeria.

The user must not be forced to report an outcome and private reports are not sold as identifiable records.

### Comparison with original build

Original: strong evidence philosophy, but citizen warnings were not a complete personal outcome loop.

V2: warning becomes measurable protection history and first-party impact evidence.

Judgment: **CLEARLY BETTER.**

## 7. The personal value screen

The app should gradually be able to answer:

**What has NaijaClimaGuard protected for me?**

Only measured or clearly estimated values may appear.

Possible proof includes:

- risky journeys avoided or changed;
- warning windows acted on;
- hours of likely disruption avoided;
- protected places monitored;
- reported loss avoided where the user confirms the counterfactual and the estimate is labelled appropriately;
- money saved only where there is a defensible calculation.

We do not invent a naira saving because it looks impressive.

## 8. Sharing: usefulness is the marketing

Every meaningful warning has a simple share action:

**Send this to someone there.**

A recipient receives a clean card with:

What
Where
When
What to do

The link opens directly to the relevant public My Tomorrow view. Registration is not required to understand the warning.

Examples of natural sharing moments:

Send Mum her warning
Share this route risk
Send this area update to the family group
Share tomorrow's shop/business outlook

### Organic acquisition loop

Useful warning → user shares → recipient sees immediate value → recipient checks own location → recipient saves something they care about → new daily user.

This is the desired growth loop. It does not depend on referral spam or artificial rewards.

## 9. Why the user pays

Basic public safety information remains free.

The upgrade appears only after the user understands the value.

Free should be enough to trust the product. Paid should feel like **more protection and less effort**.

A premium offer can eventually bundle:

- a larger number of protected places, people, routes and assets;
- household/family monitoring;
- richer personal impact planning;
- longer protection history and monthly reports;
- advanced change alerts;
- business/shop/farm views for people whose income depends on a location;
- measurable personal impact and savings analysis when the evidence exists.

The payment screen should show the user's existing benefit first rather than saying only "Unlock Premium".

Desired reaction:

**I already use this enough that losing these protections would be inconvenient. The subscription costs less than the value it gives me.**

## 10. Small-business path

A user who says "this is my shop", "this is my farm" or "this is my business" can graduate naturally into a business experience without downloading another product.

The business view can answer:

What could affect us?
When?
Which location/route/asset is exposed?
What could operations lose?
What should we change before the risk window?
What actually happened?

This creates a natural consumer-to-SME revenue path.

## 11. Enterprise data path

The citizen product generates value for companies only through aggregated, permissioned and privacy-safe intelligence.

The enterprise product should answer questions such as:

Where does a particular environmental condition repeatedly turn into real disruption?
How long does disruption normally last?
Which routes, commercial areas or asset types show repeated exposure?
Where did predicted risk become observed impact?
Which preparations are associated with lower disruption?

This is more valuable than reselling public weather data because it connects **environmental signal → Nigerian real-world outcome**.

## 12. The V2 core loop

**CHECK → UNDERSTAND → ACT → SEE WHAT HAPPENED → BUILD TRUST → PROTECT MORE → SHARE → RETURN**

Payment sits inside that loop only after trust and repeated value exist.

## Final comparison to the original submission

The original submission had the stronger proven identity today because it already exists and its flood/last-mile story is clear.

This V2 journey is **better on paper** because it preserves that warning purpose while adding personal timing, action, daily return, sharing, outcome proof, payment logic and first-party impact intelligence.

It does not earn the label **CLEARLY BETTER** merely from this document. It earns that label when the live product demonstrates:

- stronger validated model evidence;
- users understand My Tomorrow without explanation;
- users return on ordinary days as well as hazard days;
- warnings are naturally shared;
- some users voluntarily pay for deeper protection;
- the impact dataset becomes commercially useful without selling private identities.
